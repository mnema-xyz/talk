## What I checked

### 1. The alert's cause

- `scripts/test-shard.mjs` no longer has `new RegExp`. The remaining regex uses are fixed literals: `testName` (line 28/46), the spec parsers at lines 121 and 144. No argv value reaches a regex.
- The `run` mode still builds a `-run` regex from test names (`runRegex`), but those names come from `go test -list` output filtered by `^(Test|Fuzz|Example)`, not from argv, and it is passed to `go test`, not compiled in JS. Unchanged by the PR and not what the alert flagged.
- `goList` uses `execFileSync` with an argument array (no shell) and puts `--` before the patterns. A pattern with a leading dash is rejected by go itself: `pkgs 1/2 -toolexec=evil` -> `malformed import path "-toolexec=evil": leading dash`, exit 2.

### 2. Same packages as origin/main

Old script and `test-shard-weights.json` saved from origin/main into the scratch dir (weights unchanged by the PR: `git diff --quiet origin/main...HEAD -- scripts/test-shard-weights.json`).

- `old pkgs n/2 '/internal/(server|bot)$|/internal/chat(/|$)'` vs `new pkgs n/2 ./internal/server ./internal/bot ./internal/chat/...` for n = 1, 2: `cmp` identical (39 and 40 packages).
- `check-pkgs 2`: both print `79 packages, one shard each (39 + 40)`.
- Partition: `go list ./...` gives 99 packages; `go list ./internal/server ./internal/bot ./internal/chat/...` gives 20; rest-a + rest-b + those 20 sorted equals the full list, no duplicates (`uniq -d` empty). `./internal/chat/...` includes `internal/chat` itself, matching the old `/internal/chat(/|$)`.

### 3. Bash in ci.yml (lines 415-419)

- `rest=(./internal/server ./internal/bot ./internal/chat/...)` is a bash array, expanded as `"${rest[@]}"`, so each pattern is one argument and `...` is not glob-expanded (it is a literal in an array assignment; no glob characters). Works under `set -euo pipefail`: the array is non-empty, so `-u` does not trip.
- The default `run` shell on ubuntu is bash, so arrays are available. `$pkgs` stays a space-separated string, as `make GO_PKGS=` expects, same as before.
- `actionlint .github/workflows/ci.yml` (with shellcheck if installed): exit 0, no output.

### 4. Failure behaviour

- Mistyped directory: `pkgs 1/2 ./internal/srever` -> `directory not found`, exit 2. With `/...`: `no such file or directory`, exit 2. A typo fails the CI step instead of silently excluding nothing (the old regex would have excluded nothing silently).
- Regex text as a pattern: `'(a+)+$'` -> `malformed import path`, exit 2.
- Bad spec `x` -> usage, exit 2; `3/2` -> out of range, exit 2.
- No patterns: `check-pkgs 2` now succeeds over all 99 packages (old script required the argument). CI always passes patterns, and the effect would be duplicated tests, never untested packages. Acceptable.
- A pattern outside the module (`fmt`) resolves and excludes nothing, silently. Harmless: it can only make the rest shards larger, never drop a package.

### 5. Tests and repo rules

- `node --test scripts/test-shard.test.mjs`: 8 tests, 8 pass. The new test checks the observable behaviour (exact match, a shared prefix such as `server`/`serverutil` is not excluded, empty exclusion list) and is not named after coverage.
- `node scripts/check-english-only.mjs`: exit 0. Comments and usage text updated to the new argument form; no stale "regex" wording left for the exclude argument (only the `-run regex` of `run` mode, which is still accurate).
- The code is small: one exported pure helper and one `go list` wrapper. No dead code.
- Callers: only ci.yml lines 409-419 call the script; `Makefile:110` runs its unit tests; `doc/development.md:147` describes the split without naming the argument form, so it needs no update.
